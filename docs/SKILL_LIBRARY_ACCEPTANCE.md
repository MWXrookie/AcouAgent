## 0. 一句话目标

**建一个"下载即用"的本地技能库系统：随着每次成功的仿真自动积累技能，用户在门户里可视化查看与操作这些技能，并让技能在后续生成中被自动复用。**

---

## 1. 成功判据（决定"什么能进库"）

一次仿真只有**同时**满足三条才算成功：

| 条件 | 含义 | 判定来源 |
|---|---|---|
| **S1 执行无错** | `exit_code == 0` 且未超时 | executor 返回 |
| **S2 物理门控通过** | 按 §3 的分级判定达到 Q2 以上 | `physics_gate` |
| **S3 用户未表示不满意** | 用户**没有**点「结果不对」按钮 | 门户显式反馈 |

任一不满足 = 该次仿真判为**失败**，不得作为技能入库或升级的依据。

- **S3 是新增信号**：当前代码里**完全没有任何反馈通道**（`satisf`/`rating`/`thumbs`/`满意` 全库零命中），需要从零建。
- **S3 到达时机可能滞后**：用户常在下一次对话才点。因此必须支持**事后撤回**——已 `active` 的技能要能被事后降级。
- **粒度**：S3 绑定到**一次派发/一个 run_id**，不是整个对话（多轮对话里"换成 3MHz"会重跑一次完整仿真）。

## 2. 粒度模型（两级 + 派生关系）

```
L1 技能      scenario_type + preconditions        ← 一个受控场景族（"圆柱波导声场"）
   └ L2 版本  规范化参数 + 代码 + 物理证据            ← 一次具体仿真（管径 20mm/水/2MHz）
              + source_run_id + validator_version
```

- 现有 `simulation_skills` + `skill_versions` 正好对应 L1/L2 分工。
- **必须补 `preconditions` 字段**（当前整个库里没有这一列），它承载"适用边界"：几何范围、介质、频带、求解模式、维度。
- **新增派生关系**：`reference_skill_ids`（新技能参考了哪些旧技能）。
  - 现状：`skill_store.py` **没有任何 `derived_from` / `reference_skill_ids` 字段**。
  - **信任传播规则**：若 B 参考了 A，而 A 被退役/质疑 → B 必须被标记复核（复用 `runtime_registry` 已有的"退役后消费时重核"思路）。

## 3. 可验证性分级（本声明的核心新增）

| 场景类型 | 例子 | 判定方式 | 最高等级 |
|---|---|---|---|
| **受控合成场景** | 平面波、2D 点源、界面反射、频域衰减、管道/波导 | **解析解基准**（VAL-1 五类，误差 <1%） | **Q4** |
| **真实应用场景** | 操场、真实几何与边界 | **自洽性门**（下述四条） | **Q3** |
| **真实应用 + 已冻结参考基准** | 同类场景已建立基准 | **参考基准比对** | **Q4** |
| **无法验证** | 既无解析解、又无自洽证据 | 只存 candidate | **Q2** |

**自洽性门（用于真实场景，四条全过才算）**：
1. **网格收敛**：网格加密一倍，结果变化在阈值内
2. **时间步收敛**：时间步减半，结果变化在阈值内
3. **能量守恒**：声源总能量不凭空增加
4. **等价参数一致性**：换一组等价参数（单位换算/等价表达）结果对得上

> ⚠️ **诚实边界（必须写进产品文案）**：自洽性 ≠ 物理正确。自洽性门只能说"数值稳定"，**排不掉边界条件设错、单位搞错、建模假设错**这类问题。
> 因此 Q3(自洽) 技能的自动复用必须附加**前置校验**：静态检查通过 + `preconditions` 匹配 + 参数在声明范围内。

> 📌 这样设计正好落在项目已有的五级证据模型上：**自洽性门 → Q3，参考基准 → Q4**，不需要新增等级。

## 4. 积累与触发（自动化）

```
每一轮仿真结束
  → analysis 产出基础指标
  → physics_gate 定级（§3）
  → Q2 自动写 candidate
  → Q3/Q4 自动写 active（无需人工审核）
  → 写 skill_events + skill_versions
  → 记 skill_retrievals（本次用到/命中了哪些技能）
用户点「结果不对」
  → 该 run 判 S3 失败 → 相关技能 failure_count + 1
  → 触发 §5.6 规则：最近 3 次用失败 2 次 → active → questioned
```

- **触发点是"每一轮仿真"，不是整个对话**（用户已确认多轮对话里一个任务边界较明确，但每一轮都会实际跑一次）。
- **自动学习不做公开 MCP 工具**（沿用 §6.3）：只由内部流程写，避免 Prompt 或用户直接污染长期记忆。
- **自动入库的前置校验**（§5.3 要求，当前 `create_candidate` 只校验了 Q2 + 非空 + 指纹）：
  最终成功代码 · 长度 ≤20KB · 不含 Markdown/`<think>`/凭据/本机路径 · 参数可规范化 · `run_id` 可关联执行与分析 · 场景属受控枚举 · 指纹去重成功。

## 5. 可视化与操作（门户 `/skills`）

**读者：用户，不是开发人员。** 因此分层展示：默认人话摘要，原始证据可展开。

| 层级 | 内容 |
|---|---|
| 列表 | 按 `scenario_type` 分组的技能数、等级分布、状态（active / questioned / archived） |
| 详情 | 适用边界（preconditions）、**为什么可信 / 为何被质疑**、来源 run_id、代码、复用统计（含 Wilson 下限） |
| 操作 | **归档（软删除，可恢复）** · 恢复 · 标记「结果不对」 |

**"删除"= 软删除（用户已确认）**：
- 主表记录状态置为归档，列表隐藏、不参与检索与注入
- `skill_events` **append-only** 保留"何时被谁归档"的审计（这正是 §5.6"不可静默删除历史"的正确实现，**不与之冲突**）
- 当前技能库**没有 append-only 触发器**（`runtime_completion.py` 里有），需要补

**实现约束**：网关容器 `read_only: true`，`app/web/*.html` 与 `portal.py` 都打进镜像 → **改页面必须重建镜像**。现有页面家族：`/`、`/portal`、`/dashboard`、`/cache`，尚无 `/skills`。

## 7. 安全与纪律（不放松）

- 技能库不保存 API Key / Token / 完整环境变量 / 凭据 / 未清洗 stdout-stderr（§5.2）
- 技能代码**必须仍走 executor**；禁止在网关进程内 `exec()`
- executor 红线不削弱：`read_only`、`cap_drop ALL`、`no-new-privileges`、pids/CPU/内存/超时、无外网
- 本地单用户 → **不需要登录体系**；但网关默认只绑 `127.0.0.1`，避免同局域网误暴露
- 所有 `trusted_run` / `runtime_approved` / `parameters_bound` 在独立证据成立前保持 **false**
