## 2026-10-18 executor 多核 CPU 限额修正

生产升级复验发现固定平面波配方在约 18.8 秒时返回 `-9`，而 30 秒墙钟尚未到期、
executor cgroup 也没有 OOM 记录。根因是 `RLIMIT_CPU` 统计所有线程累计 CPU 时间，
旧值固定为 `timeout + 2`；双核 JAX 任务会以接近两倍墙钟速度耗尽该限额。

executor 现从 cgroup v2/v1 读取声明 CPU 配额，将累计 CPU 上限折算为
`timeout × 核数 + 2`，核数向上取整并限制在 1–8；无法读取配额时保持旧的一核预算。
executor 服务被强制为容器 PID 1，受 PID 命名空间保护；父进程正常退出或超时后会
逐层终止并回收完整后代树，调用 `setsid()` 的 worker 也不能残留。HTTP 墙钟截止仍为 30 秒，输出、进程、文件、容器内存、只读根、降权和无外网限制
均未放宽。基于当前生产科学栈、只替换候选 executor 源文件的隔离镜像已在
2 CPU / 4 GiB / internal 网络下完成原固定平面波复验：`exit_code=0`、
`timed_out=false`、回执关联通过。合并后仍需等待 GHCR 新镜像发布并在 VM 切换验证，
才能关闭发行门。

2026-10-19 终验进一步发现 executor 子进程虽然声明双线程，却通过
`xla_cpu_multi_thread_eigen=false` 关闭了 Eigen 双核路径，使默认平面波在生产 VM 上
偶发超过 30 秒。候选配置改为 `true` 后，同一未修改配方直接实测约 14.99 秒；该项在
正式镜像完成固定技能真实复用前仍保持开放，不以单次直接运行代替发行验收。

发行候选已将全新安装默认值更新为不可变 executor 标签 `f65addf`，并为上一版默认值
提供备份后迁移；仍需等待 PR 的 GitHub 干净安装门和合并后的正式 VM 复验成功后关闭。
