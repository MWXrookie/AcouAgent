## 0. 一句话项目定位

**声学仿真 MCP 服务平台**：Dify 工作流 → FastMCP 网关（:8001）→ jwave 沙箱执行器（内网）→ Markdown 报告。项目本地位于 VM `~/dify-mcp-server`（部署环境示例：内网 IP `192.168.30.200`，用户 `wenxuan`）。

## 1. 如何连接 VM（重要）

- SSH 连接方式（别名/密钥/客户端配置）见 **Owner 私发配置**，不在仓库公开（涉及个人凭据）
- 连接验证：`ssh <你的SSH别名> "echo OK"`（注意：**VM 关机时连不上**，需先开机）
- PowerShell 里执行含 `$`、引号的远程命令会被多层转义破坏，**推荐用 base64 传递脚本**：

```powershell
$script = @'
# 这里写要在 VM 上执行的 bash 脚本
echo "hello"
'@
$b64 = [Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes($script))
ssh -o ConnectTimeout=8 <你的SSH别名> "echo $b64 | base64 -d | bash"
```

- 查询 Dify 数据库时单引号会被转义污染，同样用上面的 base64 方式，或写 SQL 文件后 `docker cp` 进容器执行。

## 2. 架构

```
Dify 工作流 (nginx:80/443 + api:5001 + postgres/redis/weaviate, Docker compose)
   └→ jwave-mcp MCP 网关 (dify-mcp 容器 :8001, FastMCP 3.4.6, path=/mcp, stateless_http=True, Bearer token 认证)
        └→ jwave-executor 沙箱容器 (内网 executor_internal, Conda jwave 0.2.1, read_only, cap_drop ALL)
             └→ DeepSeek (deepseek-chat, 自动纠错 ≤7 次)
```

- 端口：`dify-mcp` 映射 `192.168.30.200:8001`；Dify nginx 暴露 `0.0.0.0:80/443`
- 数据：SQLite `/app/data/execution_history.db` + `/app/data/error_cache.db`（数据卷 `dify-mcp-server_dify_mcp_data` 持久化）
- 关键文件：`server_safe.py`（网关+工具+校验）、`dashboard.py`（门户/看板/测试报告 API）、`executor/executor.py`（沙箱执行器）、`compose.yaml`、`Dockerfile`
- Dify 中已配置：MCP provider `jwave-mcp`（token 加密存储）、应用「声学仿真」(agent) 与「仿真」(workflow)，工作流 graph 引用 `jwave-mcp` + `jwave_code_with_retry` 工具 + 代码节点

## 7. 同步约定（本机 ↔ VM）

- 本机镜像在桌面（当前 DSH 工作区），**本机为编辑源，VM 为运行源**
- 改代码：本机编辑 → tar/scp 推回 VM → VM `docker compose up -d --build`
- 拉新：VM `cd ~/dify-mcp-server && tar czf /tmp/x.tgz --exclude=".git" --exclude=".env" --exclude="*.log" --exclude="__pycache__" --exclude="executor/jwave-env.tar.gz" --exclude=".claude" .` → scp → 本机解压
- ⚠️ `.env` 只在 VM 上存在（含密钥），本机镜像不含，勿创建/勿提交
- VM 项目 270MB 中 268MB 是 `executor/jwave-env.tar.gz`（构建镜像用），同步时排除
