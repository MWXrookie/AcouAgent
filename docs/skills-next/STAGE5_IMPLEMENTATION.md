# 阶段5：用户添加、编辑与验证技能

日期：2026-10-26。阶段4已通过五项CI并建立 `checkpoint/skill-stage4-20261025`（d46192a，PR #33）。阶段5为默认关闭的独立候选，生产和main尚未切换。

## 用户路径

从技能库进入“添加与编辑技能”。管理员令牌只留在当前页内存，刷新/锁定即清除；没有多用户身份或公共上传接口。

1. 下载或导入 B01/B02/B03 标准 JSON；填写名称、说明、来源并编辑完整物理参数、代码和结果合同。
2. 严格校验后保存草稿。每次编辑以revision检查并保存不可变版本；冲突须读取当前内容，不能覆盖其他操作。
3. 查看受控求解代码的真实diff，明确应用后生成新版本。原模板主动终止，服务端不静默替换为可信代码。
4. 选择试运行或独立验证。后台共用原单并发队列、租约、fence和沙箱；试运行永不授级，未知派发只核对历史、不重跑。
5. 查看与本任务回执/完整数组绑定的热力图、幅值、RMS、轴与单位。三项精确参考只认证幅值，相位未认证。
6. 独立验证通过后显式接纳。新自然语言任务重新求解并重新核验才算实际复用；编辑新版本不继承旧job/evidence。

令牌、参考路径、profile、nonce及质量等级不能由上传内容赋予权威。页面不持久保存令牌/草稿内容；现有主题偏好仍按原机制保存。

## 实现

- `skill_authoring_api.py` 在旧动态技能路由前装配 `/skills/api/v1/`，旧接口保持兼容。64KB流式请求、2秒读请求预算、严格重复键/非有限数/深度/字段检查；稳定脱敏错误与JSON Pointer。
- `skill_manual_worker.py` 使用AUTHORING/VALIDATION开关，不依赖LEARNING；验证与接纳仍要求GENERAL_ADMISSION。启动只读核对schema18，无迁移/安装参考副作用。全局队头、单slot、prepared/unknown恢复规则不变；validated不会自动接纳。
- 页面支持模板、JSON导入/导出、版本/CAS、代码差异、任务恢复、取消、原运行对账及结果摘要下载；可聚焦错误摘要和字段定位，移动端不横向溢出。
- 结果读取重核原始历史、回执、manifest和实际数组字节；用户stdout里的PASS、错误声明或上传哈希不作为认证依据。
- 浏览器实测发现模型会漏回已明确给出的result_spec；`local_workflow` 因此增加完整结构化频域声明保留逻辑。它严格校验用户原始JSON，不从技能补参、不默认单位、不接受重复键或伪造质量；场景冲突拒绝。最终报告显式返回本次 `execution_reuse_verified`，不把交付参考当执行。
- schema仍为显式18；无19，无executor、安全、依赖锁或生产配置变更。公开schema收窄到当前真正支持的二维频域格式，跨字段物理检查由原SkillSpec继续执行。
