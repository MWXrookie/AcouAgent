## 1. 执行与留证规则

按阶段0探针→草稿/作业→接纳→复用的顺序推进。以下步骤使用拟接口/组件的功能名，实施时绑定[数据与任务合同](DATA_API_CONTRACT.md)的具体路由和服务器状态；未实现时记录“未实现”，不得打印合成PASS。接口状态词若演进，必须同步合同和用例，不能悄悄把blocked/unknown当success。

每次验收记录`case_id、执行UTC、Git SHA、配置/运行时清单、操作者、actual/expected、run_id/job_id/attempt、服务器证据引用、PASS/FAIL/BLOCKED/SKIP、缺陷ID`。涉及数值还需原始复场摘要、profile/validator/reference摘要、E及阈值；涉及迁移需前后库快照与完整性摘要。数据库与安全验证用临时副本/独立卷，实际生产数据只做授权备份与只读对账，不向生产注入攻击或清库。

所有“应拒绝”同时核对：API/作业给出稳定拒绝原因、没有active新版本、没有消费不相关证据、无重复执行/模型费用或越权文件；仅UI报错不够。没有条件执行则留BLOCKED，不计PASS。

## 6. 恢复、费用与失败语义

| ID | 故障注入位置 | 可观测通过条件 |
|---|---|---|
| REC-01 | queued后、claim后、派发前分别终止worker并重启 | 可恢复状态继续同一job；attempt/lease可追溯；无无主永running |
| REC-02 | 派发完成但run绑定持久化前终止，实际是否执行未知 | 标unknown并先查执行事实/对账；不自动重派、不把超时当未执行；操作者看到明确原因 |
| REC-03 | 完整产物已保存但比较未完成时终止 | 校验产物摘要后继续可信比较；不重跑executor，不重取模型费用 |
| REC-04 | 比较完成、接纳事务提交前/后终止 | 事务前可安全重试；事务后返回既有结果；版本/事件/证据消费恰好一次 |
| REC-05 | SQLite锁/磁盘满/比较器异常/产物丢失或摘要不符 | 稳定失败或阻断态，不显示成功；恢复不绕过证据、预算或安全边界 |
| REC-06 | 验证排队/运行时BYOK过期，重新提供凭据后恢复 | 凭据只在受限服务端生命周期内；blocked_credentials可恢复同一job；不写SQLite/日志/浏览器持久存储；实际已执行步骤不重复 |
| REC-07 | 模型调用耗费后失败；用户取消；预算到达；连续重试 | 记录实际调用/执行计数，取消最终生效、重试有界；不以后台作业绕过30秒单次executor硬墙钟 |
