# 下一阶段技术与实施计划：自动学习、用户添加技能

日期：2026-10-23。状态：准备与首批数值探针完成，阶段1/2内部实现已完成候选验证，待PR集成；用户入口和自动学习闭环仍待后续阶段。详见[准备报告](skills-next/PREPARATION_REPORT.md)。
本文件取代上一版仅列重点的 NEXT_STAGE_PLAN，作为下一轮开发与验收顺序。

## 1. 目标与可行性结论

- 最终交付：真实仿真结果可自动转成技能，经独立验证后自动接纳，并在后续自然语言任务中实际复用；用户也可按同一标准手动添加技能。
- “自动学习”指技能代码、参数、适用条件、证据的积累与复用，不涉及训练或微调模型权重。
- 自动路径在操作者开启学习后，对已支持验证类别无需逐条人工审批；手动路径在填写/导入后，由用户启动验证。两条路径共用接纳与复用机制。
- 统一格式、用户编辑入口、SQLite 持久化在现有栈内可行。新配置的可信接纳与复用属于核心工程扩展，必须通过阶段 0 的实际技术探针确认。
- 第一版限定为能独立验证、能在现有沙箱预算内求解的类别；未支持验证的技能可保存、明确标记并试运行，不能自动升级或检索注入。
- 不承诺任意代码、任意材料或复杂三维场景均能自动认证。既有 17 项固定技能与 v1.0 开放门继续保留。

## 2. 查阅资料与技术判断

以下均于本轮实际检索/读取；它们提供设计依据，不证明本项目功能已实现。

| 原始资料 | 支持的事实 | 本项目采用的判断 |
| --- | --- | --- |
| [Voyager 论文](https://arxiv.org/abs/2305.16291) | 执行反馈、验证、可执行技能积累与检索可形成学习循环，论文场景为 Minecraft | 借鉴闭环；声学可信性必须另建独立数值验证，不能套用游戏任务的成功判定 |
| [Pydantic JSON Schema](https://docs.pydantic.dev/latest/concepts/json_schema/) 与 [Strict Mode](https://docs.pydantic.dev/latest/concepts/strict_mode/) | 可从模型生成 Schema，并限制隐式类型转换 | 用统一模型生成表单/JSON 契约，显式限制字段、大小、单位与有限数值；实际版本需验证并锁定，不直接升级现有依赖 |
| [SQLite 事务](https://www.sqlite.org/lang_transaction.html) 与 [WAL](https://www.sqlite.org/wal.html) | 多读单写，BEGIN IMMEDIATE 仍可能 SQLITE_BUSY | 保留 SQLite、本地存储和短事务；执行/模型调用不得占写锁，唯一约束与有界重试保证幂等 |

| [OWASP 上传指南](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html) | 上传需校验内容/大小/权限，不可信任 Content-Type | 首版只收受限 JSON 或表单，不收任意 ZIP，不运行上传验证脚本；结果文本安全展示 |
| [j-Wave 官方文档](https://ucl-bug.github.io/jwave/) | 支持时变与时谐波动求解 | 两类结果契约要区分；当前锁定 jwave 0.2.1 的具体接口与耗时另做探针，不能据最新版文档直接假设兼容 |

## 3. 已核对的当前架构与缺口

- 保留 Web 门户、项目内 local 编排、FastMCP、SQLite、jwave executor；Dify 继续为兼容后端。
- candidate_intake 绑定实际运行来源，create_candidate 强制普通候选为 Q2，候选不参与可信检索。
- skill_local_catalog 只有既有 17 项精确配置；skill_local_profile 对配置、配方摘要、验证器和执行证据做绑定。
- skill_retrieval 先筛 active/Q3/Q4，后续仍核对受控来源与交付权限；仅改变质量等级或 SQL 状态不能使新技能合法复用。
- skill_consistency_admission/reference 仍有独立物理证据未满足即拒绝的边界，不能把自洽或签名直接当成全面物理认证。
- skill_api/service 尚无通用创建、编辑、JSON 导入入口；现有手动接纳开关不是通用用户上传能力。
- schema17 没有编辑草稿、持久验证任务和参考资产元数据结构；现有执行后补记候选机制不能替代完整任务恢复。

## 4. 确定采用的目标技术方案（待实现）

1. **两入口、一套内容结构**：自动路径从受控执行历史取实际内容；手动路径使用表单或标准 JSON。统一 schema_version、名称/说明、场景、单位化参数、适用条件、代码及预期结果声明。
2. **内容与可信证据分开**：用户可填写用途和参考来源；实际 run_id、nonce、执行回执、校验器身份、质量等级及激活状态由服务端生成/核验。JSON 中自授可信字段直接拒绝。
3. **草稿与技能分开**：编辑草稿不伪装为已有真实来源的 Q2。草稿、验证任务与产物索引通过追加迁移实现；复用现有 skills/versions/events，不建立第二个技能库。确切表名和版本在阶段 1 冻结。
4. **持久、有界验证任务**：任务存 SQLite，使用短事务领取和租约/心跳；首版每个部署限制验证并发，不能突破原执行器总体资源边界。进程重启可恢复状态，过期执行标记待核对，避免盲目重复派发。
5. **一套验证接纳服务**：新增受服务器控制的验证器注册和执行绑定适配。验证器按受支持物理类别工作，不为每条新技能再硬编码一个固定配方。禁止上传验证器代码或仅信任技能 stdout 自述。
6. **扩展真实复用权限**：验证通过后形成可审计的受控技能配置记录，贯通检索、生成决定、参考交付与执行后核验。旧固定目录保持原路径，新路径不得跳过证据重核或恢复被撤回技能。
7. **验证范围有限且明确**：先认证精确参数；扩展参数范围必须通过额外验证点与类别规则。比较端验证源、单位、网格、边界条件、结果类型和求解版本，参考数据不提供给被测生成/执行代码。
8. **事务与跨库一致性**：学习任务和技能登记采用幂等键与追加事件；运行历史只读关联并重核摘要。不能假定不同 SQLite 库的一组写入天然原子，使用可恢复步骤和对账避免半完成升级。
9. **保持部署边界**：继续 SQLite 和原 executor，不引入 Milvus、Open Interpreter、Redis/Celery 等新服务。若后续负载实测要求独立 worker，再做单独架构评审。

以上是拟建能力，不修改当前运行架构图。每个实际实施阶段必须同步真实变更到 architecture.json，重生成 HTML 并完成既定架构校验。

## 5. 分阶段开发列表

### 阶段 0：技术探针与验收冻结

- 冻结基线版本、原 17 技能行为和两套 30 题材料的用途，选至少三项非原固定目录配置作为新技能验收目标。
- 先用其中一项完成预算内求解、完整数值导出、独立比较和执行证据绑定；确认 jwave 0.2.1 实际接口。
- 明确从 candidate 到可信交付的所有代码门，形成新增受控配置的贯通方案；检查内容、参数和验证的绑定条件。
- **出口**：首项探针有真实数值、误差、耗时、来源和版本；无法通过时调整类别，不放宽原误差或资源限制。此时只证明方案关键路径，不称自动学习产品已完成。

### 阶段 1：统一技能格式与存储基础

**候选实现已完成，默认关闭、未部署。** 实现范围与恢复流程见 [阶段1说明](skills-next/STAGE1_IMPLEMENTATION.md)。任务/产物表仅建结构，执行恢复在阶段2；统一表单在阶段5。

- 定义 SkillSpec v1，复用既有 scenario_type/state_text/normalized_params/code_template/preconditions/postconditions 的含义。
- 增加结果类型、单位、坐标/采样、验证类别与来源描述；可信证据独立建模。JSON Schema、模板、表单和服务端使用同一字段来源。
- 实现草稿/任务/产物索引的追加迁移、内容摘要、幂等与乐观并发；核查“同场景参数、不同代码”的既有指纹行为，明确新版本/冲突规则，不能静默覆盖。
- **出口**：正确模板可保存；缺参、重复 JSON 键、NaN、未知字段、伪造评级、超限内容正确拒绝；升级不破坏旧库且可按备份恢复。

### 阶段 2：统一执行结果与可恢复验证基础

**内部试运行候选已实现，默认关闭、未部署。** [阶段2说明](skills-next/STAGE2_IMPLEMENTATION.md)列明恢复、资产预算和真实三题链路；目前只有稳态复压力trial，无独立科学认证、HTTP/UI或自动启动。

- 区分瞬时压力、全时最大幅值和单频稳态幅值；统一数组形状、单位、网格、复相位与完整导出契约。
- 实现持久任务领取、取消、过期核对、进度和重启恢复；模型与 executor 调用在数据库写事务之外运行。
- 完整数值产物留在服务端受控存储，展示按需抽样，校验使用完整数据；SQLite 只存索引和摘要并设预算。
- **出口**：重启/断连/重复提交不会重复激活或伪造成功，图与指标一致；现有输出/超时限制不被绕过。

### 阶段 3：通用验证、接纳与复用贯通

- 为阶段 0 选定类别实现服务器维护的验证器和可信参考绑定；阈值来自各题原规则或预先冻结的工程标准。
- 检查执行来源、代码与参数绑定，再做独立数值验证；未知类别不给出假通过。不允许运行代码读取标准答案来完成验收。
- 扩展受控 profile/验证器注册机制，使固定目录外的合格内容通过现有质量等级规则接纳并能交付、重执行和核验。
- **出口**：一项原目录外技能在没有新增固定配方白名单项、没有手改数据库等级的情况下，经验证合法接纳并实际复用；错误输出、伪造证据和越界参数均被拒绝。

### 阶段 4：自动学习闭环

- 在学习开关开启后接入真实仿真完成事件，自动提取并规范化内容，登记候选，按类别触发验证和接纳。
- 模型只辅助总结/标签，不负责授予可信性。未验证的改写代码不能继承原执行证据；抽象后的模板必须重新运行和验证。
- 支持幂等补记、失败原因、学习来源、版本和自动接纳审计。把“记录候选”“验证成功”“实际复用”分别计数。
- **出口**：至少三项原目录外配置完成首次求解到后续实际复用，全程无需逐项人工批准；开关关闭不学习、验证失败不激活、重复运行不重复增技能。

### 阶段 5：用户手动添加与编辑

- 技能页新增添加入口，提供表单、模板下载、JSON 导入、字段错误定位、预览、保存草稿和启动验证。
- 手动验证共用阶段 2/3 的任务与接纳服务，展示待验证/验证中/失败/已接纳等状态，不强迫用户配置签名基础设施。
- 支持编辑生成新版本、冲突提示、来源说明和导出；未验证草稿不自动注入生成，用户可明确试运行。
- **出口**：新操作者按标准格式添加至少一项原目录外技能，独立验证接纳后在新自然语言任务中真实复用；编辑后需重验，不能继承旧证据。

### 阶段 6：反馈、回归与版本交付

- 贯通有效负反馈、隔离/撤回、重新验证、版本依赖及撤回后立即停止交付；不可凭重复学习自动复活。
- 浏览器分别走自动学习和手动添加全流程，核对看板、SQLite、任务、执行与技能版本。
- 覆盖断连重启、重复请求、并发冲突、参数越界、错单位/相位/网格、NaN、超时、伪造质量及来源等有意义负例。
- 完成原 17 技能、缓存、看板、干净安装和迁移恢复回归；队友新环境复现并录制功能演示。
- **出口**：同一候选 SHA 的证据齐全。第二模型、本地/Dify 对照、升级回滚等原发布门继续逐项关闭，不以本阶段成功替代完整 v1.0 验收。

阶段 0→1→2→3 是依赖链；阶段 3 通过后，阶段 4 与阶段 5 可并行，最后进入阶段 6。
每阶段独立提交和验证，失败不把半完成接纳写成成功，也不为了通过演示题削弱沙箱。

## 6. 主要风险与最终完成定义

- 主要风险是固定配方之外的可信授权与科学验证，而非 JSON 表单本身；阶段 0 与阶段 3 必须以实跑证明可行。
- 论文参考数组只能证明相应条件下的数值对照；用户上传的参考值或单张热力图不能自行成为可信依据。
- 现有 CPU/内存/30 秒限制不保证全部 30 道题可运行；复杂论文题是后续扩展，不设为本阶段全部通过的前提。
- 最终演示 A：未命中技能 → 独立求解 → 自动验证接纳 → 新任务命中 → 实际复用 → 可查证据。
- 最终演示 B：用户填写/导入 → 校验保存 → 启动验证 → 接纳 → 新任务实际复用 → 编辑重验/撤回。
- 两条路径都通过完整浏览器验收且保留数值与来源，才算达成“自动学习＋用户手动添加技能”。

当前代码状态和发布门见 [CURRENT_STATUS.md](CURRENT_STATUS.md)；本阶段不会直接更改发行默认学习开关，启用策略需随真实验收明确记录。
