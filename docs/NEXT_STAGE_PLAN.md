# 下一阶段：自动学习闭环与用户添加技能

确认日期：2026-10-23。状态：已排定重点，尚未实施本阶段功能。
本计划补充现有开发规划；不改变当前运行架构、数据库或发布状态。

## 目标与优先级

本阶段以两项 P0 为主线：自动学习得到可验证、可复用的新技能；用户能按现有技能库格式自行添加技能。
结果类型统一和基准对照作为这两项的验证基础同步完成。已有 v1.0 发布门继续保留，不因本计划关闭。

## 当前基础与差距

现有系统已具备质量门控学习、固定配方接纳、普通运行 Q2 候选隔离、技能检索、版本和反馈机制。
发行配置默认关闭学习。固定目录已有 17 项精确配置，但不能把这些固定配置的重新接纳当成学会了新技能。
当前门户没有本阶段要求的通用用户技能添加入口；现有内部 create_candidate 接口要求真实执行来源，不能直接拿上传内容调用。
需要补齐的是新技能的独立验证与接纳、用户添加入口及其完整可追溯闭环。

## P0-A 自动学习

- 在已有学习开关下，从真实执行记录提取候选，绑定实际参数、代码、输出摘要、来源 run_id 与执行器版本。
- 同一来源重复处理保持幂等，相同内容去重；变更参数或代码时按既有指纹/版本规则处理。
- 只有执行成功、结果 normal 且通过适用的确定性质量门，才进入相应候选或接纳流程。
- 普通运行不能仅凭模型审查、用户点赞或退出码 0 升为可复用技能。
- 对固定目录之外的新配置，增加独立验证路径：解析基准、论文/工程原始答案或既有标准认可的自洽证据。
- 证据不足继续隔离，不自动检索注入；合格后由服务端按现有质量等级标准接纳。
- 接纳后验证生成前检索、参考交付和实际执行关联；保留用户负反馈、隔离与撤回机制。
- 技能页展示学习来源、当前状态、验证结果、未通过原因和实际复用记录。

## P0-B 用户自行添加技能

在技能库页面提供“添加技能”，支持表单填写及标准 JSON 导入；提供模板下载与字段提示。
只采用一套标准格式，复用现有技能内容结构和校验规则，不另建平行技能库。
具体导入格式需在实现第一步形成带 schema_version 的契约、示例与校验器，并与现有结构兼容。

| 用户提供的内容 | 对应现有内容结构 |
| --- | --- |
| 名称、说明与用途 | 展示元数据、state_text；展示名的映射在格式契约中明确 |
| 场景类型 | scenario_type |
| 参数及单位 | normalized_params，由服务端重新规范化 |
| 适用条件与限制 | preconditions；不得由一个验证点推断连续参数范围已认证 |
| 可执行仿真代码 | code_template，沿用当前代码大小和内容限制 |
| 预期输出及验证要求 | postconditions，属于待核验声明，不是可信证明 |
| 参考资料或原始答案来源 | 来源元数据；与本机执行证据分开保存 |

source_run_id、验证器版本、代码/参数摘要、质量等级、激活状态和可信证据由服务端生成或独立核验。
用户不能通过 JSON 中填写 active、Q4 或可信布尔值绕过验证。

添加流程：填写或导入 → 结构校验与预览 → 保存待验证草稿 → 用户启动验证 → 原 executor 实跑
→ 独立质量验证 → 候选或接纳 → 后续检索复用。

草稿是待开发的编辑流程，不冒充已经有真实执行证据的 Q2 记录；本阶段不得伪造 source_run_id。
导入本身不执行代码。验证、保存与生命周期操作复用现有管理鉴权和审计要求，上传失败返回具体字段错误。
重复添加给出已有项提示；更新生成可追溯版本，避免覆盖旧证据。用户来源与自动学习来源明确区分。

## 实施顺序

1. 冻结统一内容与导入契约，明确用户字段、服务端证据及草稿到既有状态的映射；补模板与有意义的正负例。
2. 接通用户添加、预览、保存和验证入口，复用原沙箱及接纳机制。
3. 用一项固定目录外、计算预算可支持且有独立答案的配置跑通自动学习闭环，再扩展到至少三项配置。
4. 验证手动添加与自动学习都能在后续自然语言任务中实际复用，完成去重、越界和负反馈测试。
5. 让队友从干净环境复现两条路径，完成浏览器交互验收和演示材料；之后按原发布门收口。

## 阶段出口

- 自动学习：关闭开关不写入；开启后，新配置首次求解、候选记录、独立验证、接纳与第二次实际复用均有证据。
- 手动添加：至少一份正确格式技能从添加到验证、接纳、检索和实际执行走通；与自动学习使用同一内容标准。
- 接纳准确：已知错误答案、NaN/全零、超时、错单位、错结果类型和无效来源均不能误接纳。
- 权限准确：伪造高质量等级、激活状态、run_id 或验证证据的导入被拒绝；畸形/超限内容有明确提示。
- 范围准确：参数越界不继承认证；去重、更新、撤回、已撤回项不再注入均通过。
- 展示准确：时域最大值、瞬时场和稳态幅值明确区分；截图不能替代完整数值或复数场比较。
- 来源准确：导入参考答案与实际求解输出分开，禁止把读入答案、渲染参考图作为实际求解通过。
- 基础能力：原 17 项技能、纠错缓存、看板和安装流程回归通过；SQLite、executor 安全与资源限制保持。

验收使用新收集的论文/工程基准时，沿用原题参数、评分定义与出处。
已有阶段一的冻结 30 题与新收集的 30 道数值基准是两套材料，不能混用通过数或声明全部已支持。
