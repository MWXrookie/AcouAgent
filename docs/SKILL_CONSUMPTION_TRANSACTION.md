状态：设计、连接复用及同DB测试消费原型；不是生产授权。2026-10-08。

## 核对事实与已实施部分
host_consumption_prototype根撤回/签名/去重在临时独立DB的BEGIN IMMEDIATE内；SkillStore派生检查原来另开只读连接。分别通过不能推出同一授权决策。
新增SkillStore._inspect_derivation_connection供内部协调器复用已有事务，不开启连接、不commit、不rollback；原公开只读检查仍使用预算连接。测试证实WAL旧读快照可继续读旧active状态，新快照才看见questioned；所以快照一致不等于撤回线性化。
现有技能库及根账本不迁移、不合并，不修改生产DB。ATTACH加多个WAL库不能作为跨库崩溃原子性的依据，本方案不使用它。

## 最小接口合同（未实现协调器）
服务端固定库连接，BEGIN IMMEDIATE；同一权威库内依次核对：
1. 根最新revision及撤回、独立宿主主体批准和有效期；
2. 签名中的实际请求/响应、目标image/container/start、实际参数/代码摘要与独立派发一致；
3. 固定技能版本代码哈希、边界及最新派生生命周期；
4. 与同run/代码/参数绑定的确定性物理门控，五类VAL-1误差要求不变；
5. 插入一次性消费及使用审计，run/nonce唯一；提交成功后才交付代码。
任何缺失/失败/过期/冲突均不交付，重放不是幂等授权成功。新根批准和撤回必须串行进入同一权威库；跨库只导入不可变证据不足以代表最新撤回，不能通过调用方传入true/回调补足。
读连接 helper 只是第3步复用，尚无正向协调器。单事务占用有预算，不能在持锁期间进行网络/模型/仿真；外部证据先采集，事务内重新核对版本/有效期及消费唯一性。

## 无法由开发代理自行决定的人工输入
需要用户指定生产信任主体：是否由用户管理的Ubuntu宿主独立代理负责签名、批准公钥根及撤回。模型、网关、技能代码均不得自行注册生产信任根或宣称其批准。
推荐范围：独立于网关/技能的宿主代理，固定目标jwave-executor，仅观察原始请求与响应和最小Docker身份，不把Docker socket或私钥交给网关，不对外开放端口，不记录凭据/原始代码/stdout。具体服务接线、密钥保管/根批准、撤回责任须由用户确认；当前不创建凭据或启动服务。
这项身份和责任选择影响真实认证关键路径；可继续完成独立代码，但不能用更多格式测试冒充通过。
